# Security Policy

## Do not report vulnerabilities publicly

Do not include vulnerability exploit details, secrets, credentials, tokens, private host/network/device data, or sensitive logs in public Issues or Discussions.

Use GitHub private vulnerability reporting when it is enabled for this public repository.

If private vulnerability reporting is temporarily unavailable, do not publish the vulnerability. Open only a non-sensitive public issue stating that you need a private security contact, without technical exploit details.

## What belongs in a normal bug report

A normal public bug report may include reproducible behavior that does not reveal a security vulnerability or sensitive environment data.

## Scope

Security reports may concern the canonical Control Plane, Local AI runtime, Host Observability, Network/Cyber Security provider, Devices provider, Demo/Management Center, public packaging, or public interfaces. Maintainers will route the report internally without exposing private repository state.

## Disclosure

Do not assume a public report, fix branch, or patch can be disclosed before maintainers explicitly publish a safe disclosure. Security remediation remains subject to canonical Authority, verification, and evidence requirements.
